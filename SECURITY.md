# Security policy

## Supported versions

Before the first stable release, security fixes are made on the latest default branch. After 1.0, the latest stable release line and the default branch receive security fixes.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, pull request, discussion, or log excerpt.

Use GitHub's **Report a vulnerability** button on the repository Security page to submit a private report. Include:

- the affected version or commit;
- impact and realistic attack scenario;
- reproduction steps or a minimal proof of concept;
- suggested mitigation, if known.

Remove credentials and unrelated private data. Maintainers will acknowledge and investigate reports on a best-effort basis and coordinate disclosure after a fix is available.

If private vulnerability reporting is temporarily unavailable, open a public issue containing no vulnerability details and ask maintainers for a private contact channel.
